本版聚焦**分区刷写**的能力补齐与**字库备份**的交互重做，并把这一轮新增的界面文案全部纳入 10 个语言包。

设备信息卡在「型号」下面新增一行：

```
型号     PJZ110 (PJZ110)
平台     高通
构建版本  ...
```

- 探测逻辑与字库备份、分区刷写共用 `PartitionUtil.detectPlatform()`：
  高通 → `/dev/block/bootdevice/by-name`，联发科 → `/dev/block/by-name`。

## 二、刷写：刷入分区镜像新增「展示所有分区」

入口：**刷写 → 刷入 → 刷入分区镜像**。

### 2.1 两种模式

「刷入分区镜像」标题下方新增一个整宽按钮，两态切换：

| 模式 | 按钮文案 | 列表来源 |
|---|---|---|
| 预设（默认） | 展示所有分区 | `boot`、`dtbo`、`init_boot`、`recovery`、`system_dlkm`、`vbmeta`、`vendor_boot`、`vendor_dlkm` |
| 全部 | 切换至预设分区列表 | 平台节点目录下**实际存在**的全部分区（按名字排序） |

- 全部模式是懒加载：只在第一次进入时 `listFiles()` 扫描节点目录，加载中显示「正在检索分区节点…」，扫不到显示「未找到可用的分区节点」。
- 每个分区仍是一个刷写按钮：点击 → 选择 `.img` → 二次确认（确认弹窗中的目标路径显示真实节点，例如 `/dev/block/by-name/init_boot_a`）→ 刷写，与预设列表完全一致。

### 2.2 槽位过滤规则

以**当前所在槽位**为准：

| 打开位置 | 列表内容 |
|---|---|
| A 槽 | 隐藏所有带 `_b` 后缀的分区 |
| B 槽 | 隐藏所有带 `_a` 后缀的分区 |
| A-only 设备 | 不过滤，全部展示 |

实现位于 `SlotViewModel.loadAllPartitions()`，按 `slotSuffix` 分支过滤后写入 `SnapshotStateList`，因此每个槽位各自维护自己的列表与滚动状态。

### 2.3 按节点名刷写（关键变更）

预设列表的分区名是「基名」，刷写时由 `findPartitionBlockDevice(name, slotSuffix)` 拼出 `name + 后缀`；但全部模式里的名字本身就是完整节点名（`init_boot_a`、`persist`、`bootloader` …），再拼后缀会变成 `init_boot_a_a`，必然定位失败。

因此本版新增了一条独立的刷写路径：

- `PartitionUtil.findPartitionNode(name)`：按 `by-name` 节点直取。
- `PartitionUtil.findMappedPartitionNode(name)`：`/dev/block/mapper/<name>`，用于判断该分区是否为 dynamic partition。
- `PartitionUtil.partitionNodePath(name)`：只用于确认弹窗里展示路径。
- `SlotViewModel.flashImage()` 重构为 `flashImageCore(...)`，新增 `flashImageNode(context, uri, nodeName)`：
  - 目标是 mapper 节点 → 按逻辑分区处理：把 `name` 拆成 `base + _a/_b` 后走 `flashLogicalPartition()`（`lptools remove/create/unmap/map/replace`，必要时 `resize` + 重新挂载）；
  - 否则 → 直接 `flashBlockDevice()`（比大小、必要时清零、按 SHA-256 边写边算）。
- 自动备份同步支持：`AutoBackupManager.backupNode(context, nodeName)` 按节点名 dd 备份，与 `backup()` 共用同一套目录 / `backup.yml` / `summary.json` 逻辑。
- UI 侧新增 `flashActionType = "flashImageNode"`，确认弹窗文案、目标路径、结果页跳转均按新类型接好。

> 已知边界：逻辑分区若当前**未映射**（`/dev/block/mapper/<name>` 不存在），列表里仍会显示该 by-name 条目，点击刷写会提示 `Partition ... was not found` —— 这是安全失败，不会误写其它分区。

## 三、刷写板块：活跃槽位置顶

- 「刷写」页的槽位顺序改为：**活跃槽位永远在最上面**，另一槽位在分隔线之后；非 AB 设备仍是单块。
- A/B 两段重复的操作列表抽成 `SlotActionItems()`，文案由「槽位后缀 + 是否活跃」推导，不再出现「B 段写死 B 文案」的错位：

| 操作 | 活跃槽位 | 非活跃槽位 |
|---|---|---|
| 刷写 | 选择 AK3 / 镜像刷入 | 刷写到 B 槽位 |
| 备份 | 备份当前槽位到本地 | 备份 B 槽位 |
| 恢复 | 从历史备份恢复 | 从历史恢复 B 槽位 |
| 检查内核 | 从 boot 镜像中提取内核版本 | 检查 B 槽位内核版本 |

- `vendor_dlkm` 的挂载 / 映射按钮改为绑定当前块的 `SlotViewModel`（此前固定绑 A 槽）。
- 去掉两处残留的「刷入 KernelSU 驱动」字样（该入口在 v2.9 已移除）。

## 五、字库备份改版

### 5.1 分区勾选

扫描完成后，「开始字库备份」右侧的 `ⓘ` 按钮打开分区列表：

- 每行：勾选框 + 分区名 + 大小，点整行也能切换；
- 单个「全选 / 全不选」切换按钮（全选后点一下即全不选），顶部实时显示 `已选 N / M 个 · 1.2 GB`；
- 底部标注被跳过的 `userdata / sdc`；
- 开始按钮副标题显示已选数量与预计占用，未选任何分区时置灰。

### 5.2 备份页布局

自上而下：

1. **信息栏**：未完成时标题为「工作信息」，行 `将备份的分区总数`、`备份目录`；完成后原地变为「备份结果」，行 `成功 / 跳过 / 失败 / 备份目录 / 分区信息`（高度变化用 `animateContentSize()` 过渡）。
2. **进度**：总进度（已完成 / 待备份）+ 当前分区进度（已写入字节 / 分区大小，复制过程中每 200 ms 轮询目标文件大小）。
3. **日志区**（无标题）：每完成一个分区打印 `Backup 'init_boot' ==>[OK]`，失败为 `==>[FAIL]`，失败的分区会删除半成品 img。
4. **悬浮按钮**：成功后从底部滑入「返回备份设置」，由 `RefreshableScreen` 新增的 `bottomOverlay` 槽位承载，不参与滚动、不占布局，因此出现/消失不会把内容顶来顶去。

### 5.3 BPINFO.xml

备份完成后在备份目录生成 `BPINFO.xml`（Backup Partition Information）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<BackupPartitionInformation version="1" device="PJZ110" platform="高通" source="/dev/block/bootdevice/by-name" backup="/sdcard/ReKernelFlasher/backups/PJZ110字库备份" createdAt="2026-11-27T22:41:07" hashAlgorithm="SHA-256" partitionCount="3" totalSize="134217728">
  <Partition name="boot" source="/dev/block/bootdevice/by-name/boot" file="boot.img" size="100663296" hash="9f2c1e0b…"/>
  <Partition name="init_boot" source="/dev/block/bootdevice/by-name/init_boot" file="init_boot.img" size="8388608" hash="3a7bd3e2…"/>
  <Partition name="dtbo" source="/dev/block/bootdevice/by-name/dtbo" file="dtbo.img" size="25165824" hash="c0d5f7c7…"/>
</BackupPartitionInformation>
```

- 每条 `<Partition>`：分区名、源节点路径、img 文件名、字节大小、SHA-256；
- 生成逻辑抽成纯函数 `BpInfoWriter.build()`（XML 转义、总量汇总），有 4 个单测覆盖；
- 哈希优先用系统 `sha256sum`，缺失时回退到应用自带的 `busybox sha256sum`。
